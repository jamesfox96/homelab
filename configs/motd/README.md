# roach — custom login banner

Replaces Ubuntu's default MOTD with a friendly, informative welcome message.

## What it shows

- **ASCII banner** — colored ASCII-art hostname
- **Host info** — OS, kernel/arch, IP, uptime
- **System status** — CPU load, memory, CPU temp
- **Disks** — every real filesystem with free space (yellow ≥80%, red ≥90%).
  Mounts listed in `EXPECTED_MOUNTS` show a red "NOT MOUNTED" if missing.
- **Services** — Jellyfin + the full *arr stack + download clients, with
  running/stopped status and whether each is enabled on boot. Only services
  that actually exist on the box are listed.
- **Containers** — every Docker container (running or not) with its state,
  uptime and health check result, plus a yellow restart count for containers
  Docker has had to restart after crashes. One `docker ps` and one
  `docker inspect` call, each capped at 2s.
- **Updates** — pending apt updates, with a separate red "security update(s)
  required" line when any are waiting, plus a reboot-needed warning.
  `apt-check` takes ~1s, so it never runs inline: the banner shows the cached
  result from `/var/cache/roach-motd/apt-check` and refreshes it in the
  background whenever apt/dpkg state changes (or every 12h). The very first
  login after install shows "checking…"; the next one has the numbers.
- **Recent logins** — last 5 logins, newest first, from `wtmpdb` (Ubuntu
  26.04+), then `last`, then sshd entries in the journal as a fallback.

## Deploy (run on the server as root)

1. Copy the script to the MOTD directory:

   ```sh
   sudo install -m 755 01-custom-banner /etc/update-motd.d/01-custom-banner
   ```

2. Disable the stock Ubuntu MOTD scripts. **Nothing is deleted** — we just
   remove the execute bit, which stops them from running. They stay in place
   and are fully recoverable with `chmod +x`.

   ```sh
   sudo chmod -x /etc/update-motd.d/00-header /etc/update-motd.d/10-help-text \
                 /etc/update-motd.d/50-motd-news /etc/update-motd.d/80-esm \
                 /etc/update-motd.d/80-livepatch \
                 /etc/update-motd.d/90-updates-available \
                 /etc/update-motd.d/91-release-upgrade \
                 /etc/update-motd.d/95-hwe-eol \
                 /etc/update-motd.d/98-reboot-required \
                 /etc/update-motd.d/99-linux-firmware
   ```

   The `chmod -x` approach keeps all files intact — easier to undo than moving
   or deleting them.

3. Test it the way pam_motd runs it (as root, empty environment), and time it:

   ```sh
   time sudo env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin bash /etc/update-motd.d/01-custom-banner
   ```

4. Log out and back in to see it on the real login screen.

### Reset / undo

Every default script is still there — just restore their execute bits:

```sh
sudo chmod +x /etc/update-motd.d/00-header /etc/update-motd.d/10-help-text \
              /etc/update-motd.d/50-motd-news /etc/update-motd.d/80-esm \
              /etc/update-motd.d/80-livepatch \
              /etc/update-motd.d/90-updates-available \
              /etc/update-motd.d/91-release-upgrade \
              /etc/update-motd.d/95-hwe-eol \
              /etc/update-motd.d/98-reboot-required \
              /etc/update-motd.d/99-linux-firmware
```

(Or simply `sudo chmod +x /etc/update-motd.d/*` to restore all of them.)

## Notes

- Colors are real ANSI escape sequences (built with Bash `$'...'` quoting), so
  they render in any normal terminal. They're defined up top if you want to
  tweak the palette.
- The MOTD is generated by root once per login and shown to everyone, so it
  doesn't greet by username (`$USER` is empty under pam_motd).
- Anything that could hang (`systemctl`, `docker`, `df`, `journalctl`) is
  wrapped in `timeout`, so a stuck daemon or mount can't stall your SSH login.
- If `apt-check` is missing, the script shows a hint instead of failing.
- If Updates is stuck on "checking…", look at
  `/var/cache/roach-motd/refresh.log` (errors from the background refresh).
- The `Last login: …` line under the banner isn't from this script. It comes
  from sshd (`PrintLastLog no` in `/etc/ssh/sshd_config.d/` hides it) or, if
  that doesn't work, from a lastlog line in `/etc/pam.d/`.

## Customize

- Change the ASCII art or hostname in the banner block.
- Add/remove entries in the `services` and `pretty` arrays (keep them in
  parallel order). WireGuard is listed as `wg-quick@wg0`; change the
  interface name if yours differs. (On roach the media apps run in Docker, so
  they appear under Containers instead.)
- `EXPECTED_MOUNTS` lists drives that must be mounted — currently
  `/mnt/storage` (the NVMe media drive). Add or remove paths as needed.
